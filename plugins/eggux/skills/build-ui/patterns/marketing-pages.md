# Marketing pages

Shell: `Page Shell / Marketing`. Blocks on the Hero, Sections, Content and Navigation pages,
grouped by family inside each page's `Blocks` section.

## Which block
| Family | Blocks | Use |
|---|---|---|
| Banner | Announcement Banner, Banner with Action, Banner Countdown, Banner Floating | Announcement Banner for site-wide news on primary, above the Navbar; Banner with Action for events and notices on the muted band; Banner Countdown only for a real dated offer; Banner Floating at the bottom for a launch. One banner at a time, dismissible |
| Hero | Hero Centered, Hero Split, Hero with Screenshot, Hero with Logo Cloud, Hero with Form, Hero with Phone, Hero Full-bleed Image, Hero with Video, Hero with Stats, Hero Image Collage, Hero Prompt | Pick by what sells the product: the screen (with Screenshot; with Logo Cloud adds customer logos), a human or illustrative image (Split), a brand photo (Full-bleed Image), people (Image Collage, for people-centered products), a product tour (with Video), scale and track record (with Stats), one email field (with Form), a mobile app (with Phone, store badges). Hero Prompt for the signed-in home of a portal or data product where people start by asking (AI search or assistant). All 11 side by side in `Example / Hero showcase` (Hero page) |
| Logo Cloud | Logo Cloud, Logo Grid, Logos Split, Logo Marquee | Marquee right under the hero; Grid as its own customers section; Split for partners or investors with one sentence of context |
| Features | Features, Features Split, Bento Grid, Bento Grid 2, Features with Screenshot, Features Tabs, How It Works, Feature Checklist, Integrations Grid | Grid for 3-6 short benefits (Feature Item, stacked); split rows for deep-dives; Bento Grid and Bento Grid 2 for a platform overview with real components; with Screenshot for one area proved by its screen; Tabs for 3-5 areas of one product; How It Works for a setup or process in 3-4 steps; Checklist for what every plan includes; Integrations Grid for "does it work with our tools" |
| Trust | Security and Compliance, Trust Strip | Security and Compliance on enterprise and finance pages before Pricing (controls and the certifications you hold); Trust Strip as a one-line reassurance row under a store hero or above the footer |

| Contact | Contact, Contact Cards, Contact with Map, Offices, Map Section | Cards for channels; map variants only when people visit; always the written address next to a map |

| FAQ | FAQ, FAQ Grid, FAQ Centered | Grid when answers are 1-2 sentences; accordion for longer answers; end with a contact option |

| Team | Team, Team Grid, Team List | Grid with photos for the company page; List with bios for leadership and investors |
| About | About Hero, Mission with Figures, Our Story, Values | The About page, in this order, then Team, a testimonial, partners (Logos Split) and a CTA |
| Page headers (Page Headers page) | Header Detail, Header Listing, Header Search Results, Header Profile, Header Event, Header Topic, Header Report, Header Simple | Top of inner pages, by page type: see § Page headers. Landing pages use Hero |

## Page headers
Every inner page starts with the header for its type, right under the Navbar. One h1, one
primary action at most.

| Page | Block | Says |
|---|---|---|
| Product, dataset, service, solution | Header Detail | What it is (badges for type and scope), who is behind it, the main action; media on the right. Details and a Table of Contents follow |
| Hub or listing (resources, insights, library) | Header Listing | What is here; a type switch that filters the list; search that keeps the type |
| Search results | Header Search Results | The query, still editable; count; tabs by type with counts; sort |
| Person (author, expert, speaker) | Header Profile | Name, role, organization, short bio, three counts, follow and contact |
| Event, webinar | Header Event | Format, date and time with time zone, place or online, speakers, register and add to calendar; after the date, Watch the recording |
| Topic, category, tag | Header Topic | Scope in one line, how much and how fresh, subtopics as Chips, follow |
| Report, study | Header Report | Three headline figures with their source; download and read online |
| Legal, about, policy | Header Simple | Title, one sentence, last updated; centered at 720 |

Related links in an aside or under an article: `Post Card` Layout=compact, 3-5 items.
Event lists under Header Event or on a topic page: `Event Card`. Downloads on a detail page:
`Resource Item` rows in a card. A strong line between sections: `Quote` Variant=pull.

## Typical order (landing page)
1. Navbar (Navbar Mobile below 768; mega menu panels open on click, close on Escape)
2. Hero: one promise, one primary CTA, one secondary
3. Logo Cloud: proof right after the promise
4. Features (3-6), How It Works, Stats
5. Testimonials; Security and Compliance for enterprise buyers
6. Pricing, then Comparison Table for the details
7. FAQ
8. CTA band, Newsletter
9. Contact (when sales talk to every customer)
10. Footer

Full examples on the Showcase page of the library: `Example / Showcase / Orbitly SaaS` (Showcase
Light), `Meridian Enterprise` (Corporate Light), `Lumora AI product` (Showcase Dark) and
`Tidewater store` with its product page (Light). Each alternates default and muted bands, uses
one decorative device and real imagery; start a landing page by copying the closest one.

## Rules
- One primary CTA repeated (same label) in Hero, Pricing and the final CTA band.
- Each section answers one question; its Section Header title says the answer, not the topic.
- Logos in one muted color; real customers only, with permission.
- Integrations Grid shows only tools the product really integrates with, as `Logo / *` swaps in
  Logo Tiles; inside the product, use Block / Integrations with connect states.
- Trust Badges name the certificate and what backs it (audit date, scope); never a badge without
  the report behind it.
- Team: real photos or initials, name and role; link to bios only if they exist.
- Contact: response time promise, direct channels, short form (name, email, topic, message);
  inline success with what happens next.
- Comparison Table: plans as columns (recommended marked), features grouped, check / dash /
  value; mobile shows one plan at a time. On pricing pages use `Comparison Table` Plans=3 or 4 to
  match the plan cards, in the same order.
- Sections alternate background only when it helps scanning (`background/default` / `muted`).
- Testimonials: real name, role and company (Byline); specific results beat praise; no stock photos.
  One `Testimonial Card` Variant=featured above a grid of default or logo cards; minimal quotes for
  a quiet row under a hero.
- Hero, CTA and page header buttons sit in an Action Bar (start, or center under centered text);
  one primary.
- Maps: never the only way to find an address; add directions and opening hours; lazy-load
  interactive maps and use a static image above the fold.
- Banners: one at a time, dismissible, not for errors or outages.
- Gallery grids use `Image Figure`; office grids use `Location Card` with Show map (Block / Offices).
- Event grids with long titles: Event Card `Date position=image`.
- Block / Hero Split: Media=image for a photo, Media=screenshot for a Device Frame; Show trust for
  Trust Badges under the actions.
- Hero Prompt: Accent is the greeting, Title stays on two lines, Suggestions holds 2-4 Prompt Suggestions; submitting opens the chat or results page with the question prefilled.
- No gray boxes on a finished page: hero and feature visuals are product screenshots (`Image / Screenshot / *` in a Device Frame); people, places and products use the Imagery photos (Image Placeholder `Show image`, Avatar Type=image); logo clouds use `Logo Tile` with a different `Logo / *` per tile. All are samples to replace with the client's own.
- Hero headlines use `display/lg` with one accent phrase in `foreground/brand`; section titles use `heading/h1`, eyebrows `foreground/brand`.
- Put Stats, Logo Cloud, Testimonial Grid or FAQ on `section/muted-background` between default sections (Light neutral/50 keeps muted text at 4.5:1). Never use `background/muted` for a full-width band.
- One decorative device per page: a `Background / Grid`, `Dots`, `Glow` or `Beam` (Grid + Glow together count as one hero treatment) as the first child of the hero or one CTA band, absolute positioned, stretched, aria-hidden. Never behind dense content; keep body text off the glow core and beam heads, and check muted text stays 4.5:1 over it.
- Feature, step and bento icons sit in an `Icon Tile`: neutral by default, brand for one accent grid, gradient for one highlighted item; one Style per grid. Feature Item holds an exposed Icon Tile: set Style=brand (or gradient) on the nested tile; do not override the tile fill or icon color.
- To show a client's brand on a pitch or cover, set the frame to their mode; the `Showcase Light` / `Showcase Dark` modes and the pages on Showcase show what a rebrand does to the same blocks.
- Every CTA gets a secondary action and a proof row (Avatar Group with photos and a Rating with a count).
- On a primary band or card, use Inline Form and Figure Tone=on-primary (secondary button, text in
  `foreground/primary`), no manual overrides; captions use `foreground/primary`.
- Device Frame: put an `Image / Screenshot / *` in Screen at Fill width and resize the frame, never
  the screen; the height follows the image. Set a fixed screen height only to crop on purpose.
- To put a Background behind a hero, turn off `Show background fill` on Hero Centered (and `Show panel fill` on Hero Prompt) instead of clearing fills.
- A block with its own decoration (CTA Card glow) counts toward the one-device rule; turn `Show decoration` off when the page has a Background.
- Set the brand with the `Logo` property on Navbar and Footer blocks (any `Logo / *` or the client logo).
- Keep a hero `Background / Grid` at about 30% layer opacity so muted text over grid lines stays 4.5:1.
- Never hide items inside a block's grid to change the count (the grid keeps its rows); pick the block whose count fits.
- On a full-bleed photo hero keep the text white over the block scrim and measure the brightest pixel under it (4.5:1); skip the accent phrase there.
- Over a full-bleed photo or video use Block / Navbar Style=on-image (white on `video/scrim`)
  instead of a Dark mode override; turn on Show cart for shops.
- Logo Marquee fades use `gradient/background-transparent`; on a muted band rebind the fades to
  the band color.
- In dark modes alternate `background/default` and `section/muted-background` per section and keep cards on `background/card`; light product screenshots become the brightest area, so give them a Device Frame and space around.

## Cookie consent
- Needed before any non-essential cookie (analytics, ads, embeds that track). Necessary cookies
  need no consent but are listed.
- Accept all and Reject all have the same weight and sit side by side; Customize opens the
  preferences. Optional categories start off. Never block the page or hide Reject.
- Remember the choice; a "Cookie settings" link in the footer reopens the preferences.
- Marketing sites: `Cookie Consent` Type banner at the bottom. Apps: Type card in the
  bottom-left corner. Preferences: Type preferences (dialog with Switches; Necessary always on).
- Texts: say what each category does in one line; link the cookie policy. Legal review per
  country; record the decision in `decisions.md`.

## Related components
- Use `Countdown` only for real deadlines (offer end, webinar start, registration close), always
  with the exact date, time zone and what happens at zero. Never reset it to create urgency.
  Style=default (muted tiles) for banners, cards and checkout; boxed for hero sections, launch and
  webinar pages on a muted or image background; inline for tight spaces (a sticky bar, a table
  cell, a resend-code line). One Style per page.
- Pricing blocks are built from `Plan Card` (2-4 side by side, one recommended plan as
  Variant=featured or inverted, never both; Variant=compact rows for 4+ plans and add-ons), `Price`,
  `Check Item` (5-8 per plan) and a `Toggle Group` for monthly or yearly with a success Badge for
  the saving (example "billing period" on the Toggle Group page). Logo Cloud uses `Logo Tile` in
  one muted color; testimonial blocks use `Testimonial Card`. `Price` Size=xl once per page, in a
  pricing hero or a single-offer section.
- Above a hero title, one `Announcement Pill` links to the newest launch. "How it works" sections
  use `Feature Item` Marker=number (3-4 steps). Certifications in footers, pricing and security
  sections use `Trust Badge`; product screenshots sit in a `Device Frame`, one frame style per page.
- `Feature Item` Layout=card for feature grids on muted or busy sections, or when each item links
  to its own page; the whole grid uses card. Stacked stays the default for short benefits.
